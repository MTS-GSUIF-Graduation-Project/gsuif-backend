# Business-rule regression fixtures

`duplicate-component.json` is a minimal structurally valid snapshot with a
duplicate component ID. `route-context.json` records a project and route that
already exist together. `MetadataBusinessFixtureTest` replays both files against
their named business rules.

From the repository root, replay the fixtures and pinned jqwik properties with
Java 21 and the Spring test profile:

```sh
./mvnw -B -Dspring.profiles.active=test -Dtest=MetadataBusinessFixtureTest,MetadataBusinessValidatorPropertiesTest,MetadataBusinessMutationEngineTest test
```

On Windows, use `.\mvnw.cmd` in place of `./mvnw`. The property methods in
`MetadataBusinessValidatorPropertiesTest` declare seeds 51001–51005. The
mutation-engine test reruns each targeted property with the same seed and compares
the recorded failing samples; its concise output names the property, seed, mutant,
result, and sample count. The exact-size boundary is generated by
`BusinessRuleTestSupport.sized(bytes, duplicate)` at 4,999,999, 5,000,000, and
5,000,001 UTF-8 bytes.
